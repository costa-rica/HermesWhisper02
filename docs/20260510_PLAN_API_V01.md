## Decisions baked in

| Topic         | v1 choice                                                                           |
| ------------- | ----------------------------------------------------------------------------------- |
| Topology      | Ubuntu `fsdc-avatar08` runs API + Hermes; reverse proxy `Maestro04` fronts TLS.    |
| Mac dev       | Hermes is **mocked** locally (`HERMES_MOCK=true`); no Hermes binary on Mac.         |
| Front LLM     | **OpenAI** (`gpt-4o-mini`) via Pipecat OpenAI service. Abstraction kept.           |
| STT / TTS     | **OpenAI Whisper / OpenAI TTS** (`tts-1`).                                          |
| Pipeline      | **Serial first, parallel later.** Phase 6 builds serial; Phase 8 refactors to `ParallelPipeline`. |
| Python        | 3.13 on Mac, 3.12 on Ubuntu. `pyproject.toml` requires `>=3.12,<3.14`.              |
| Tooling       | `uv` for venv + lockfile. `ruff` for lint+format. `pytest` for tests.               |
| Auth          | Carry HermesVoice 2FA design (email code → bearer). SMTP via Gmail per B-2 answer.  |
| Persistence   | SQLite at `DB_PATH`, schema authored fresh (no fork from HermesVoice).              |
| Logging       | Loguru per `docs/LOGGING_PYTHON_V06.md`.                                            |
| Errors        | Per `docs/ERROR_REQUIREMENTS.md`.                                                   |

## Phase 3 — WebSocket transport + protocol envelope

**Goal:** `/ws/voice` accepts an authed client, exchanges `client_hello` ↔ `session_started`, and echoes audio frames. No Pipecat yet — this isolates protocol bugs.

Tasks:

- [ ] `routes/voice_ws.py`: bearer auth on connect (query param fallback `?token=` for clients that cannot set headers on WS — keep behind a flag, off in prod).
- [ ] Implement protocol envelope per `20260510_PROTOCOL_V01.md` §3.
- [ ] On connect: parse `client_hello`, emit `session_started`, persist a `voice_session` row.
- [ ] Loop: read text/binary frames; for now, server emits a dummy `transcript` after every 1 s of audio and an `audio_chunk` prelude + binary echo for testing.
- [ ] Implement `cancel_turn` (closes the current dummy turn) and `client_bye` (server closes WS cleanly).
- [ ] Tests: `pytest` WS test using `httpx_ws` or `starlette.testclient.TestClient` to drive a mock client.

Acceptance:

- A test client can connect, send `client_hello`, receive `session_started`, send a binary frame, receive an `audio_chunk` prelude + binary echo.
- Unauthorized connects close with `error: AUTH_FAILED`.

Commit: `feat: add /ws/voice envelope and session lifecycle (PLAN_API phase 3)`.

- [ ] `services/front_llm.py`: build `OpenAILLMService` with `FRONT_LLM_MODEL`, register the `call_hermes` tool per REQ §6.1, supply the system prompt:

On small talk and trivial clarifications, answer directly without the tool. Vary phrasing of acks; never use the same ack twice in a row.

- [ ] Tests: with `HERMES_MOCK=true` and a real OpenAI key, drive the smoke WAV and assert the assistant produces (a) an ack TTS chunk and (b) a follow-up answer TTS chunk.

## Phase 8 — Refactor to `ParallelPipeline` for ack/answer

**Goal:** Cut perceived latency by emitting the ack TTS while the Hermes tool call is still streaming.

Tasks:

- [ ] Read Pipecat's `ParallelPipeline` docs and pick a fan-out point (likely after `context.user`).
- [ ] Restructure `services/pipeline.py`:
  ```
  ws_in → vad → stt → context.user → ParallelPipeline(
    [front_llm_ack → tts_ack],          # short ack path
    [front_llm_answer → tts_answer],    # tool-calling path
  ) → ws_out → context.assistant
  ```
- [ ] Tag downstream `audio_chunk` frames with `source: "ack" | "answer"` accordingly.
- [ ] Ensure barge-in (`UserStartedSpeakingFrame` mid-answer) cancels both branches and emits `turn_end {canceled: true}`.
- [ ] Compare p50/p95 of `end_of_user_speech → first_ack_audio_byte` against Phase 5 baseline. Update `20260510_LATENCY_BASELINE.md`.
- [ ] If the parallel split materially regresses correctness or stability, revert to serial and file an open question — do not block downstream phases on parallel.

Acceptance:

- Smoke test still passes; ack TTFB improves vs. Phase 5 baseline.
- Barge-in cancels both branches within NFR-3.

Commit: `refactor: split pipeline into parallel ack/answer (PLAN_API phase 8)`.

## Cross-cutting policies

- **No web client.** Confirmed in REQ §1.2.
- **No CORS.** The API serves only the iOS app over WSS. Add CORS only if a future track requires it.
- **No PII in logs.** Email and 2FA codes are logged at DEBUG only and only in `RUN_ENVIRONMENT=development`. Bearer tokens are never logged.
- **Secrets.** Never commit `.env`. `/etc/hermes-whisper-02/env` is root-owned mode 600 on the Ubuntu box.
- **Tests vs. integration.** Tests requiring live API keys or a live Hermes are marked `@pytest.mark.integration` and skipped by default. CI (if added later) runs only unit tests.

## Risks specific to this plan

| Risk                                                         | Mitigation                                                     |
| ------------------------------------------------------------ | -------------------------------------------------------------- |
| Pipecat version churn breaks the pipeline mid-build          | Pin in `pyproject.toml`, lockfile in repo, upgrade on a branch |
| OpenAI Whisper non-streaming busts NFR-1                     | Phase 5 records baseline; if blown, switch to Deepgram early  |
| `ParallelPipeline` (Phase 8) destabilizes the pipeline       | Revert path documented; Phase 8 is reversible                  |
| Python 3.12/3.13 mismatch causes a dep that needs 3.13 only  | Lockfile resolved against 3.12 floor; CI / Ubuntu builds first |
| Hermes contract differs from HermesVoice                     | Phase 9 starts with a discovery step before implementation     |
