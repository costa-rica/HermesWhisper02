## Decisions baked in

| Topic         | v1 choice                                                                           |
| ------------- | ----------------------------------------------------------------------------------- |
| Topology      | Ubuntu `fsdc-avatar08` runs API + Hermes; reverse proxy `Maestro04` fronts TLS.    |
| Mac dev       | Hermes is **mocked** locally (`HERMES_MOCK=true`); no Hermes binary on Mac.         |
| Front LLM     | **OpenAI** (`gpt-4o-mini`) via Pipecat OpenAI service. Abstraction kept.           |
| STT / TTS     | **OpenAI Whisper / OpenAI TTS** (`tts-1`).                                          |
| Pipeline      | **Deterministic ack processor + serial answer path** for v1. Ack TTS fires from a small templated processor the moment STT finalizes a transcript, independent of the front LLM. The front LLM owns routing and the substantive answer only. `ParallelPipeline` becomes optional polish (Phase 8) since most of its win is already captured by the split. |
| Python        | 3.13 on Mac, 3.12 on Ubuntu. `pyproject.toml` requires `>=3.12,<3.14`.              |
| Tooling       | `uv` for venv + lockfile. `ruff` for lint+format. `pytest` for tests.               |
| Auth          | Carry HermesVoice 2FA design (email code → bearer). SMTP via Gmail per B-2 answer.  |
| Persistence   | SQLite at `DB_PATH`, schema authored fresh (no fork from HermesVoice).              |
| Logging       | Loguru per `docs/LOGGING_PYTHON_V06.md`.                                            |
| Errors        | Per `docs/ERROR_REQUIREMENTS.md`.                                                   |

## Phase 3.5 — Pipecat transport adapter spike

**Goal:** Prove the custom JSON-prelude + binary protocol can be exposed as a Pipecat transport `input()`/`output()` pair, before any pipeline work depends on it. Codex review (Codex API §2) flagged the transport seam as the highest hidden-rework risk.

Tasks:

- [ ] `pipecat_processors/ws_transport_adapter.py`: subclass / wrap Pipecat's FastAPI WebSocket transport.
  - Input side: convert incoming binary frames into Pipecat `InputAudioRawFrame` at 16 kHz mono PCM16; surface JSON control frames (`client_hello`, `cancel_turn`, `client_bye`) as Pipecat custom events without injecting them into the audio stream.
  - Output side: serialize `TTSAudioRawFrame` as `audio_chunk` JSON prelude + a single binary WebSocket message of exactly `bytes` bytes; serialize Pipecat speaking-state events into `user_started_speaking` / `user_stopped_speaking`; serialize errors into the project error envelope.
  - `turn_id` and `source` (`ack` | `answer`) propagate end-to-end via Pipecat frame metadata.
- [ ] Replace `routes/voice_ws.py`'s hand-written loop with a Pipecat pipeline that has just `transport.input() → passthrough → transport.output()`. Audio echo from Phase 3 still works through this path.
- [ ] Tests: drive the same fixtures from Phase 3 through the adapter; assert prelude/binary pairing, control-event isolation, and clean shutdown.

Acceptance:

- All Phase 3 tests still pass against the adapter-backed `/ws/voice`.
- Adapter has no STT/TTS/LLM dependencies — it is pure transport translation.

Commit: `feat: add pipecat ws transport adapter (PLAN_API phase 3.5)`.

## Phase 7 — Persistence integration + session resume

**Goal:** Conversations are durable and resumable per protocol §4.4.

Tasks:

- [ ] On `client_hello` with `session_id`, look up `voice_sessions`; if owned by `current_user` and within resume window (env `SESSION_RESUME_WINDOW_SEC`, default 300), rehydrate the front-LLM context from `voice_messages`.
- [ ] **Define what "finalized" means for a turn** (Codex API §8). A turn is `completed` only when its `answer` audio reaches `turn_end` without `canceled=true`. An `ack` whose `answer` was canceled is `canceled` overall, even though the ack audio played.
- [ ] On every state change, write to the `turn_state` table created in Phase 1: `started` when STT finalizes, `first_audio` timestamps recorded as ack and answer each begin, `completed` / `canceled` / `failed` on `turn_end`. Persist `voice_messages` only for turns that reach `completed`.
- [ ] On reconnect, the resume path reads `turn_state` to skip turns that were `canceled` or `failed` mid-flight, so the rehydrated LLM context contains only completed exchanges (idempotency required by NFR-5).
- [ ] Tests: simulate disconnect mid-turn, reconnect with `session_id`, verify `session_started.resumed=true`; verify a canceled mid-turn does not appear in the rehydrated context; verify the same `turn_id` cannot be replayed.

Acceptance:

- Resume happy path passes.
- Resume rejected for foreign owner returns a fresh session.

Commit: `feat: persist conversations with resume (PLAN_API phase 7)`.

## Phase 8 — Optional: refactor to `ParallelPipeline`

**Goal:** Only execute this phase if Phase 6 measurements show the deterministic ack still has noticeable serialization cost (e.g., ack TTS audibly waits on LLM/TTS contention). With the deterministic ack already independent of the LLM, much of `ParallelPipeline`'s benefit is captured; this phase is **polish, not a v1 requirement**.

Decision criteria before starting Phase 8:

- Phase 6 latency baseline shows `end_of_user_speech → first_ack_audio_byte` p95 > 1500 ms (NFR-1 miss) **and** profiling confirms the cost is in pipeline serialization, not in STT, TTS, or network.
- Otherwise: skip Phase 8 and proceed to Phase 9.

Tasks (if executed):

- [ ] Read Pipecat's `ParallelPipeline` docs and pick a fan-out point (after `context.user`).
- [ ] Restructure `services/pipeline.py`:
  ```
  ws_in → vad → stt → context.user → ParallelPipeline(
    [ack_processor → tts],              # deterministic ack branch
    [front_llm (router/answer) → tts],  # answer branch (tool-calling)
  ) → ws_out → context.assistant
  ```
- [ ] **Merge rules** required by Codex API §5:
  - Ack audio may begin first; answer audio must not interleave at the binary-frame level with an incomplete ack chunk.
  - `turn_id`, `source`, and `seq` remain monotonic per `source`.
  - Barge-in cancels TTS, LLM generation, and Hermes streaming together.
- [ ] Compare p50/p95 of `end_of_user_speech → first_ack_audio_byte` against Phase 6 baseline. Update `20260510_LATENCY_BASELINE.md`.
- [ ] If the parallel split materially regresses correctness or stability, revert. Do not block downstream phases.

Acceptance:

- Smoke test still passes; ack TTFB improves vs. Phase 6 baseline.
- Barge-in cancels both branches within NFR-3.

Commit: `refactor: split pipeline into parallel ack/answer (PLAN_API phase 8, optional)`.

## Cross-cutting policies

- **No web client.** Confirmed in REQ §1.2.
- **No CORS.** The API serves only the iOS app over WSS. Add CORS only if a future track requires it.
- **No PII in logs.** Email and 2FA codes are logged at DEBUG only and only in `RUN_ENVIRONMENT=development`. Bearer tokens are never logged.
- **Secrets.** Never commit `.env`. `/etc/hermes-whisper-02/env` is root-owned mode 600 on the Ubuntu box.
- **Tests vs. integration.** Tests requiring live API keys or a live Hermes are marked `@pytest.mark.integration` and skipped by default. CI (if added later) runs only unit tests.
