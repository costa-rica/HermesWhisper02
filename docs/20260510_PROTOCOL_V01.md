# HermesWhisper02 — WebSocket Protocol v1

**Date:** 2026-05-10
**Status:** Draft v0.1 — frozen contract between mobile and api tracks.
**Source of truth for:** REQ §5.2 (frame definitions).

This document is the contract between the iOS app and the FastAPI/Pipecat backend. **Both tracks must conform to this doc.** Changes require a version bump and a coordinated mobile + api change.

---

## 1. Endpoints

| Method | Path                  | Auth                     | Purpose                                |
| ------ | --------------------- | ------------------------ | -------------------------------------- |
| POST   | `/api/auth/login`     | none                     | Start 2FA — sends email code           |
| POST   | `/api/auth/verify`    | none                     | Exchange email code for bearer token   |
| GET    | `/api/server/info`    | none                     | Probe — used by registry-add flow      |
| GET    | `/api/health`         | none                     | Liveness probe (200 OK)                |
| WS     | `/ws/voice`           | `Authorization: Bearer`  | Voice session                          |

Base URL in production: `https://api.hermes-whisper.dashanddata.com`.

## 2. REST contracts

### 2.1 `POST /api/auth/login`

**Request:** `{ "email": "...", "password": "..." }`
**Response 200:** `{ "ok": true, "expires_in": 600 }` (code valid for 10 min)
**Errors:** `AUTH_FAILED` (401), `VALIDATION_ERROR` (400)

### 2.2 `POST /api/auth/verify`

**Request:** `{ "email": "...", "code": "123456" }`
**Response 200:** `{ "token": "<bearer>", "expires_at": "2026-06-09T12:00:00Z" }`
**Errors:** `AUTH_FAILED` (401), `VALIDATION_ERROR` (400)

### 2.3 `GET /api/server/info`

**Response 200:**

```json
{
  "name": "fsdc-avatar08",
  "version": "0.1.0",
  "front_llm": "openai:gpt-4o-mini",
  "auth": "bearer-2fa",
  "protocol_version": 1
}
```

### 2.4 Error envelope

All errors follow `docs/ERROR_REQUIREMENTS.md`:

```json
{ "error": { "code": "...", "message": "...", "status": 400, "details": null } }
```

## 3. WebSocket envelope

`/ws/voice` carries two frame kinds:

- **JSON text frames** for control/metadata. Always a single JSON object with a top-level `"type"` field.
- **Binary frames** for raw audio (PCM16 LE, 16 kHz, mono uplink; downlink format announced by `audio_chunk` prelude).

### 3.1 Audio framing rule

Each binary audio frame from server → client is **immediately preceded** by a JSON `audio_chunk` prelude that announces `bytes`, `format`, `seq`, `turn_id`, and `source`. Clients buffer the prelude and consume exactly `bytes` from the next binary frame. This lets us interleave ack and answer audio safely.

Uplink audio (client → server) needs no prelude; the server treats every binary frame as PCM16 LE 16 kHz mono per `client_hello.sample_rate`.

## 4. Frame catalog

### 4.1 Client → server (text)

| `type`             | Payload                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------ |
| `client_hello`     | `{ "protocol_version": 1, "session_id"?: str, "downlink_format": "pcm16", "sample_rate": 16000, "ptt_mode": bool, "intermediary_mode"?: "deterministic" \| "llm", "audio_params"?: object }` |
| `cancel_turn`      | `{ "turn_id"?: str }`                                                                            |
| `set_intermediary_mode` | `{ "mode": "deterministic" \| "llm" }`                                                        |
| `set_audio_params` | `{ "speech_rms_threshold"?: float, "end_silence_seconds"?: float, "min_turn_seconds"?: float, "max_turn_seconds"?: float }` |
| `ping`             | `{ "ts": float }` — app-level heartbeat (every 15 s); server replies with `pong`                 |
| `client_bye`       | `{}`                                                                                             |

### 4.2 Server → client (text)

| `type`                  | Payload                                                                                              |
| ----------------------- | ---------------------------------------------------------------------------------------------------- |
| `session_started`       | `{ "session_id", "conversation_id", "downlink_format", "sample_rate", "front_llm", "resumed": bool, "created"?: bool }` |
| `user_started_speaking` | `{ "ts": float }`                                                                                    |
| `user_stopped_speaking` | `{ "ts": float }`                                                                                    |
| `transcript`            | `{ "turn_id", "text", "is_final": bool }`                                                            |
| `assistant_text`        | `{ "turn_id", "text", "final": bool, "ts": float }`                                                  |
| `assistant_state`       | `{ "state": "ack" \| "thinking" \| "answer" \| "idle" }`                                             |
| `hermes_progress`       | `{ "turn_id", "kind": "sent_to_hermes" \| "response_started" \| "tool_call" \| "tool_result" \| "finished" \| "preparing_audio" \| "audio_ready" \| "failed", "text": str, "ts": float }` |
| `runtime_config_applied` | `{ "fields": [str], "values": object }`                                                            |
| `audio_chunk`           | `{ "turn_id", "seq": int, "format": "pcm16" \| "opus", "sample_rate": int, "bytes": int, "source": "ack" \| "answer" }` |
| `turn_end`              | `{ "turn_id", "canceled"?: bool }`                                                                   |
| `pong`                  | `{ "ts": float }` — heartbeat reply, echoes client's `ts`                                            |
| `error`                 | full error envelope from §2.4                                                                        |

### 4.3 Lifecycle

```
C: (open WS with Authorization: Bearer ...)
C → S: client_hello
S → C: session_started

(loop)
C → S: <binary PCM frames continuously>
S → C: user_started_speaking
S → C: user_stopped_speaking
S → C: transcript {is_final: true}
S → C: assistant_state {state: "ack"}
S → C: audio_chunk {source: "ack", seq: 0, bytes: N}
S → C: <binary N bytes>
... (more ack chunks)
S → C: assistant_state {state: "thinking"}
S → C: hermes_progress {kind: "sent_to_hermes", text: "..."}
S → C: hermes_progress {kind: "response_started", text: "..."}
S → C: hermes_progress {kind: "tool_call", text: "..."}
S → C: hermes_progress {kind: "tool_result", text: "..."}
S → C: hermes_progress {kind: "finished", text: "..."}
S → C: assistant_text {final: true, text: "..."}
S → C: hermes_progress {kind: "preparing_audio", text: "..."}
S → C: hermes_progress {kind: "audio_ready", text: "..."}
S → C: assistant_state {state: "answer"}
S → C: audio_chunk {source: "answer", seq: 0, bytes: M}
S → C: <binary M bytes>
... (more answer chunks)
S → C: turn_end {turn_id}
S → C: assistant_state {state: "idle"}

(barge-in: user speaks during answer)
S → C: user_started_speaking         (client immediately mutes playback)
S → C: turn_end {turn_id, canceled: true}
(loop continues)

(shutdown)
C → S: client_bye
S: close
```

### 4.4 Runtime config

`client_hello.intermediary_mode` is optional. If omitted, the server defaults to `"llm"`.

- `"deterministic"` routes substantive transcripts directly to Hermes and bypasses the front-LLM router.
- `"llm"` keeps the front-LLM router behavior.

`client_hello.audio_params` and `set_audio_params` can include any subset of:

- `speech_rms_threshold`
- `end_silence_seconds`
- `min_turn_seconds`
- `max_turn_seconds`

Runtime config changes apply at the next turn boundary. The WebSocket loop may be busy processing an active turn, so clients must not expect `set_intermediary_mode` or `set_audio_params` to change the turn already in progress.

The server clamps out-of-range values and echoes the accepted values in `runtime_config_applied`. The `fields` array names changed fields, and `values` contains the effective clamped values.

### 4.5 Assistant text

The server emits `assistant_text` after Hermes streaming finishes and before `turn_end`. `assistant_text.final=true` means the `text` field contains the assembled assistant response for the turn. If a turn is canceled, the server must not emit `assistant_text.final=true` for that turn.

### 4.6 Session resume

On reconnect within a configurable window (default 5 min), client sends `client_hello.session_id` of the prior session. Server responds with `session_started.resumed=true` and rehydrates front-LLM context from the persistent store. If resume is rejected, server returns a fresh `session_id` with `resumed=false`.

## 5. Versioning

`protocol_version` starts at `1`. Breaking changes bump this. Server announces its supported version in `GET /api/server/info.protocol_version`; mobile refuses to connect if the major version differs from what it was built against.
